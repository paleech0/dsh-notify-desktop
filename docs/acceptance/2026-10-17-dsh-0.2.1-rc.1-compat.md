# 兼容性验证：dsh-notify-desktop vs DSH 桌面端 0.2.1-rc.1（2026-10-17）

> 环境：DSH 桌面端 **0.2.1-rc.1**（nightly 通道，Electron 44，Windows 11）；插件 `dsh-notify-desktop` 0.1.0。
> 装配：desktop profile 以 `link:` 指向本仓库（与工作区副本的 lib 哈希一致）。
> 结论：**兼容，无需改代码**。版本闸门、插件加载、会话投影、客户端决策、宿主 Toast / 文件音效 / 静默、失焦端到端链路均通过。

## 1. 版本闸门

- 运行时 `"<DSH 桌面端安装目录>\resources\runtime\cli\bin\dsh.cmd" --version` = **0.2.1-rc.1**；`DeepSeek Harness.exe` fileVersion = 0.2.1-rc.1。
- 插件声明 `dsh.engines.dsh = ">=0.2.0-rc.2 <0.3.0-0"`；用运行时自带 semver 7.8.5 计算：
  `satisfies("0.2.1-rc.1", ">=0.2.0-rc.2 <0.3.0-0", {includePrerelease:true}) = true`
  （注意：**不带** `includePrerelease` 时为 false；宿主闸门带该选项。）
- 宿主闸门实现未变：有 `engines.dsh` 时只看它、忽略 peer 依赖，不满足则整层 patch 跳过。profile 无 `compatibility.json`，无需放行。

## 2. 仓库自检

`pnpm run check` 全绿：`tsc --noEmit` → vitest **12 个文件 / 77 个测试**通过 → rolldown 构建成功；
重建后的 `lib/index.js`、`lib/client.js` SHA256 与升级前完全一致（构建确定性，`lib/` 无漂移）。

## 3. 运行中实例实测（16:38 升级后重启的实例）

- 16:39:01 客户端上报 `client bundle loaded`、`notification permission=granted`；7 个会话的投影均有 `notify`/`title` 状态；
  后续持续产生 `scan ... projection=...` 与 `turn N reason=completed ...` 决策行 → 客户端决策管线在 0.2.1 正常。
- 宿主路由：`GET /dsh-notify/foreground` → `{"focused":true}`；`/sound-library`（作者音效 4 + 自定义 2）、`/sound-cache`、`/questions` 均 200；
  `POST /dsh-notify/toast` → 204 并**真实弹出通知**（`file:ding`，`media.soundPlayers=1`）；`POST /dsh-notify/silence` → 204 立即停止（`soundPlayers→0`）。
- **失焦端到端（本轮新测）**：用 Start 菜单把 DSH 窗口切到非前台（foreground 路由返回 `{"focused":false}`）→ 子代理会话结束 →
  ```
  turn 1 reason=completed focused=false -> toast
  toast delegated to host (window unfocused): notification plugin · 任务完成
  ```
  随后窗口回前台自动静音：`silence: stopped 1 sound(s)`。
  → 「失焦 → 宿主 PowerShell Toast（含文件音效）→ 回前台静音」整条链路在 0.2.1-rc.1 可用；窗口有焦点时仍按设计抑制。

## 5. 残留风险 / 维护提示（均不影响当前运行）

1. **运行时无类型声明** + devDeps 仍锁 0.2.0-rc.2：当前运行不受影响；将来按 0.2.1 类型重编时会碰到
   `@deepseek-ai/dsh-client-ui-slots` 已无独立运行时包（插件仅 type-import）、SlotMap 增强迁到 ui-settings-general 等类型级差异。
2. **装配链接指向另一份克隆**：profile 的 link 目标与工作区不是同一个目录（被 link 的副本 HEAD 为 cc38700，工作区当时为 936e24b）。
   当前 lib 哈希一致；**以后改源码后必须重建并同步到被 link 的副本（或重挂 link），否则运行时不生效**。
3. 通知依赖会话投影送达链路（host snapshot → control 帧 → `list.byId.projectionValues`，无 key 白名单）——0.2.1 仍如此。
4. 0.2.1 的 `turn/end` 新增 `interrupted` / `forked` 结局；插件 `NotifyReason` 词表仍只有
   completed/error/aborted/blocked/max-tokens，新结局按设计**静默**（不弹），是否补属产品决定，非兼容性问题。

## 6. 未覆盖项
